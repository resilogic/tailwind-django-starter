1) Django Ninja endpoint to mint V4 download URLs (GET)

# app/api/media.py
from datetime import timedelta
from django.conf import settings
from ninja import Router
from google.cloud import storage

router = Router()

@router.get("/media/{path:path}")
def get_media_signed_url(request, path: str):
    client = storage.Client(project=settings.GCLOUD_PROJECT)
    bucket = client.bucket(settings.GCS_BUCKET)
    blob = bucket.blob(path)

    # V4 signed URL, max 7 days; use short TTLs (e.g., 10–60 min)
    url = blob.generate_signed_url(
        version="v4",
        expiration=timedelta(minutes=15),
        method="GET",
        # If you front with Cloud CDN, include headers you’ll send (Host, etc.)
        # headers={"x-goog-user-project": settings.GCLOUD_PROJECT}
    )
    return {"url": url, "expires_in_seconds": 15 * 60}

— Uses official V4 signing (7-day maximum).  ￼

2) Django Ninja endpoint to mint upload URLs (PUT)

@router.post("/media/upload-url")
def get_upload_url(request, path: str, content_type: str = "application/octet-stream"):
    client = storage.Client()
    blob = client.bucket(settings.GCS_BUCKET).blob(path)
    url = blob.generate_signed_url(
        version="v4",
        expiration=timedelta(minutes=10),
        method="PUT",
        content_type=content_type,
    )
    return {"url": url, "expires_in_seconds": 600}

— Clients must PUT with the exact Content-Type that was signed.  ￼

3) Node.js server (if/when you mint in Node)

import { Storage } from "@google-cloud/storage";

export async function getSignedUrl(bucket: string, object: string) {
  const [url] = await new Storage()
    .bucket(bucket)
    .file(object)
    .getSignedUrl({ action: "read", version: "v4", expires: Date.now() + 15 * 60_000 });
  return url;
}

— Uses @google-cloud/storage getSignedUrl.  ￼

4) Next.js client: auto-refresh before expiry (no manual timer)

// useSignedMedia.ts
import { useQuery } from "@tanstack/react-query";

export function useSignedMedia(path: string) {
  return useQuery({
    queryKey: ["media-url", path],
    queryFn: async () => {
      const r = await fetch(`/api/media/${encodeURIComponent(path)}`);
      return (await r.json()) as { url: string; expires_in_seconds: number };
    },
    // Revalidate a bit early to avoid edge clock skew & caches
    staleTime: (data) => Math.max(0, (data?.expires_in_seconds ?? 0) * 1000 * 0.8),
    refetchInterval: (data) => Math.max(30_000, (data?.expires_in_seconds ?? 0) * 1000 * 0.9),
  });
}

— Fetches a fresh URL before it expires (works now on GCE; same later on Cloud Run).

OTHER CONSIDERATIONS:

Security & IAM
	•	Sign with a service account that has object access (typically limited to the bucket). Don’t sign with user creds.  ￼
	•	Prefer short TTLs (10–60 min) and refresh client-side; V4 URLs cannot exceed 7 days.  ￼


Networking
	•	Today on GCE (private IP): enable Private Google Access so VMs without external IPs can hit GCS APIs privately.  ￼
	•	On Cloud Run later: choose egress policy (all/all-vpc/all-private) and, if needed, attach a VPC connector or Direct VPC egress, then call GCS with the service account — no public egress required.  ￼

Caching / CDN
	•	If you need global performance, put Cloud CDN in front of private media: keep bucket private, attach backend to LB, and use CDN Signed URLs or Signed Cookies for authorization at the edge. Cookies help when one user needs many files under a single policy.  ￼CDN implementation is next, not here. 

Client refresh strategy
	•	Do not rely on auto-regen — signed URLs are opaque and expire. Have clients request a fresh URL before expiry (e.g., at ~80–90% of TTL) to avoid clock skew and caches. (Limit enforced by V4.)  ￼

Next.js Image quirks
	•	Configure images.remotePatterns exactly for your host(s) (GCS domain or CDN/custom domain). Missing or overly broad patterns cause 400s.  ￼

Operational gotchas
	•	Key rotation: if you sign using a service account’s private key, URLs minted before key rotation continue until TTL; mint new ones after rotation. (Limit still 7 days for V4.)  ￼
	•	Content-Type must match for PUT-signed uploads; mismatches yield 403.  ￼
	•	Region warnings when using gcloud storage sign-url from CLI without proper perms/flags; ensure bucket perms or pass --region.  ￼
	•	DDoS: if exposing via external LB/CDN, attach Cloud Armor (WAF, rate-limit, geo/IP rules).  ￼
